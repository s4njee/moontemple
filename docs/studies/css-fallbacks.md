# CSS fallbacks for the Tier A effects

Story 7.4. Each Tier A effect's CSS version (`src/fallbacks/css-fallbacks.ts`, drawn by `src/fallbacks/css-bokeh.ts`: radial-gradient discs, screen-blended, on a few compositor keyframes) alone in `experiments/css-fallbacks.html?only=<id>`, filling a 1280 × 720 window in headless Chrome on this machine, 2026-10-27. Each ran for 5 seconds. Main thread is Chrome's Performance metric (all tasks), as story 4.1 measured it; style is the style-recalculation part of it; GPU process is the union of the GPU process's top-level tasks from a trace, as story 6.1 measured it. All in milliseconds per second of running. `node experiments/css-fallbacks-cost.mjs` re-runs it; `experiments/css-fallbacks.html` shows each beside the effect.

The empty page costs 7.6 ms/s of main thread and 3.9 ms/s of GPU process at 61 frames a second; the rows below include it.

No CSS version:

- **aperture-lab**: The lab is the aperture: blade counts, f-numbers, the cat’s eye and the near row flipped through focus are its whole subject, and a CSS circle shows none of them. The contact sheet of apertures is the fallback.
- **lens-light**: Each piece is a lens phenomenon on its own control: spectral fringes on the discs, film halation, ghosts strung through the centre, an anamorphic streak. CSS could draw the star spikes and nothing else, which would misstate what the effect shows. The still with every effect on is the fallback.
- **rack-focus-transition**: Its CSS version is not a field of discs: `filter: blur()` and opacity on the two views, built and measured in story 6.8. It blurs without bokeh in the highlights, which is the point of the effect.

## What the run says

- **Every CSS version holds 60 frames a second** at 1280 × 720 on this machine (Apple M1 Max). Frame rate does not separate them; main-thread and GPU-process time do.
- **Main-thread time is about the empty page's 10 ms a second plus a third of a millisecond a second for each animated element**, nearly all of it style recalculation and animation ticking, even though every animation is a fixed transform or opacity keyframe on the compositor (story 4.1 found the same slope). Twenty animated elements cost little; two hundred cost 65 to 75 ms a second, 7% of a core here and more on the older devices that are the ones without WebGPU.
- **A still CSS version costs nothing**: the static gradients (ice-halo, lunar-corona) and bokeh-drift held still, as under `prefers-reduced-motion`, sit at the empty page's floor on both threads. A gradient still is a poster with no image to download.
- **The GPU process pays for any motion at all**: once anything animates, Chrome draws a frame every vsync, about 60 to 85 ms a second of GPU-process time for even a dozen elements, rising to 150 to 185 with two hundred screen-blended discs. That is the same order as the WebGPU effects themselves, so CSS is not a cheaper way to animate a dense field; it is a way to animate one without WebGPU. GPU-process times vary by tens of percent between runs on a shared machine; read them as an order of magnitude.
- **The WebGPU rows are for scale only**: bokeh-drift's shader page costs about half the main thread of its CSS version at 144 discs, and holds that at any disc count (story 4.1); glitter's shader page spends most of its main thread on its own script.

## Verdicts

- **Honest fallback**: bokeh-drift, bokeh-loader (as an indeterminate spinner), dust-in-light, fairy-lights, fireflies, glint-hover (a `:hover` glint per card), ice-halo, lamp-in-fog, light-leak, lunar-corona, night-street, snow-at-night. Bokeh is where CSS comes closest: screen-blended radial-gradient discs at the effect's sizes, palette and density read as the poster at a glance, and drift and a capped twinkle are a few keyframes. The static sky effects (ice-halo, lunar-corona) are closer still, since the effects hardly move. For the dense ones (dust-in-light, fairy-lights, snow-at-night, around 150 to 215 elements) a site should halve the count before shipping: the look survives and the main-thread time halves with it.
- **Poster is better**: focus-cursor, focus-pull, lens-model, glitter, moon-through-cloud, moonbow (provisional: written from the summary before the effect could be seen; it draws the pale bow but not the waterfall in its poster). Each one's subject is what CSS cannot do (a focus that follows the pointer or the scroll, facets that flash with the light, a lit cloud, a traced bow), so the CSS version is a costlier still.
- **Leave it out**: flare-cursor. A cursor flare that does not follow the cursor is decoration; the page works without it.
- **No CSS version**: aperture-lab, lens-light and rack-focus-transition (whose CSS version, blur and opacity, is story 6.8's), for the reasons above.
